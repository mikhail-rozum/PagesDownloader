# PagesDownloader

Console application. Asynchronously downloads a set of web pages and saves them to a directory.

Task: "Create a program to download multiple web pages asynchronously".

## Requirements

- .NET 10 SDK

## Build and Run

```
dotnet build
dotnet test
```

URLs as arguments:

```
dotnet run --project PagesDownloader.Console -- -d ./pages https://example.com https://example.org
```

Note: `--` separates `dotnet run` parameters from application parameters.

URLs from a file:

```
dotnet run --project PagesDownloader.Console -- -d ./pages -i samples/sample-50.txt
```

All the parameters:

```
dotnet run --project PagesDownloader.Console -- -d ./pages -i samples/sample-50.txt -p 16 -t 30 https://example.net
```

## Parameters

| Parameter | Alias | Default value | Description |
|---|---|---|---|
| `urls` | | | URLs separated with a space symbol. |
| `--destination` | `-d` | required | Directory to store pages. Created if it does not exist. |
| `--input` | `-i` | | Text file with URLs, one per line. |
| `--parallelism` | `-p` | 8 | How many pages to download simultaneously. From 1 to 32. |
| `--timeout` | `-t` | 60 | Timeout in seconds for one page. From 1 to 300. |

At least one URL is required: in a file or in arguments. It is possible to use both sources at the same time (both sources are merged).

File format: Single line per URL. Empty lines and lines starting with '#' are skipped.

## Exit codes

| Code | Description |
|---|---|
| 0 | All the pages are downloaded. |
| 1 | Some of the pages are not downloaded. |
| 2 | The execution was canceled by user. |
| 3 | Could not use or write into destination directory. |
| 4 | No URLs were provided. |
| 5 | Could not read file with URLs. |

## Assumptions

1) A web page is the response body. Images, CSS, scripts, etc are ignored;
2) Content of a page is saved as is. The content type is not checked;
3) Valid URL is absolute with protocol http/https. URLs with other protocols are marked as InvalidUrl;
4) Duplicates - URLs with the same protocol, host, port, path, and query string. Host and scheme are case-insensitive, path and query are case-sensitive. The fragment (#...) is ignored;
5) Duplicates are downloaded only once;
6) File name consists of: host, path, 8 characters of URL hash.

## Solution

- Parallelism is limited. Downloading is mostly waiting for network, so limit does not depend on the number of CPU cores;
- `Parallel.ForEachAsync` is used, so an available slot takes the next URL right after it gets free;
- `HttpClient` is created by `IHttpClientFactory` (typed client). User-Agent header is set: some resources may reject requests from clients that do not provide the header;
- Timeout has effect on download of one page (including page body). Built-in HttpClient timeout is disabled since it works only for receiving headers (not body);
- Timeout and cancellation by user are distinguished (status TimedOut for Timeout, cancellation stops the execution);
- If one URL download fails, it does not affect the other URLs;
- Code returns result for each URL: status, path to the file, error message;
- Command line arguments are processed by `System.CommandLine`. It also handles `Ctrl+C`;
- `Host` is used only as DI-container. It is not run;
- No retry policy. A failed download is reported right away.

## Project Structure

- `PagesDownloader.Library` - download logic;
- `PagesDownloader.Console` - command line arguments and parameters processing, download run, displaying report;
- `PagesDownloader.Tests` - Tests.

## Tests

- xUnit. HTTP and file system operations are replaced with fakes (stubs) in memory;
- Coverage: success, HTTP errors, download failures, invalid URLs, duplicate URLs, timeouts, cancellation, parallelism limit, destination directory creation, file names, URLs comparison;
- Not covered: writing on disk (FileService), command line arguments and parameters processing, exit codes. Tested manually.

## Limitations

- Two different URLs with redirect to one page will be downloaded twice;
- If the process is killed, a partially written file may remain on disk;
- No per-host request limit.

## Future improvements

1) Retry policy with increasing delay (backoff);
2) Request number limit for a host.
